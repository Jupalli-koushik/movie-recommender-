Building the movie recommender demonstrated my React skill by translating a product goal into a component-driven UI. I structured the app around an App container, a MovieComponent for search results, and a MovieInfoComponent for the detail panel. This decomposition kept responsibilities clear: the App handles search input and list state, the list item renders summary metadata, and the detail panel fetches and presents information for a selected title. Using Create React App let me focus on UI logic while still following standard React organization in src/ with co-located styling.

State management and data flow are central to the experience. I used useState to track the search query, the current list of results, the selected movie, and user-facing errors. The search field triggers onChange, and I implemented a debounce with setTimeout to avoid firing an API request on every keystroke. Axios is used for asynchronous calls to the OMDb API, and I update state based on whether the Search array exists. When a result is clicked, the selected IMDb ID is passed down to MovieInfoComponent; a useEffect hook watches that ID and fetches full details, demonstrating how to connect component lifecycle to remote data.

I also applied React patterns for conditional rendering and styling. The UI switches between a placeholder image and a grid of MovieComponent cards depending on the list length, while the detail panel only appears when a movie is selected. Error messages are surfaced in a dedicated container so users understand invalid searches or network issues. Styled-components let me encapsulate visual rules with each component, giving the header, search bar, cards, and detail layout consistent spacing and hierarchy. Overall, the project shows practical React skills: component composition, props-driven rendering, hooks for state and effects, asynchronous data handling, and a responsive, user-friendly interface that feels like a complete application.
