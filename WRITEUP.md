## Component Architecture
Building the movie recommender demonstrated my React skill by translating a goal into a component UI. I structured the app around an App container, a MovieComponent for search results, and a MovieInfoComponent for the panel. This decomposition kept responsibilities clear. The App handles search input and list state. Each list item renders metadata, and the detail panel fetches and presents information for a title. Using Create React App let me focus on UI logic while following React organization in src/ with co-located styling.

## State Management and Data Flow
State and data flow are central to the experience. I used useState to track the search query, the list of results, the selected movie, and errors. The field triggers onChange, and I implemented debounce with setTimeout to avoid firing an API request on every keystroke. Axios is used for calls to the OMDb API, and I update state based on whether the Search array exists. When a result is clicked, the selected IMDb ID is passed down to MovieInfoComponent. A useEffect hook watches that ID and fetches details, demonstrating how to connect lifecycle to remote data.

## Rendering and Styling
I also applied React patterns for conditional rendering and styling. The UI switches between a placeholder and a grid of MovieComponent cards depending on the list length. The detail panel only appears when a movie is selected. Error messages are surfaced in a dedicated container for invalid searches or network issues. Styled-components let me encapsulate rules per component. They give the header, search bar, cards, and detail layout consistent spacing and hierarchy. Overall, the project shows React skills in component composition and props-driven rendering. It also shows hooks for state and effects, data handling, and an interface that feels like a complete application for a polished user experience.
